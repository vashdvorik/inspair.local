# Окружение, интеграции и релизы (Laravel)

## Окружение и конфигурация
- Поддерживайте актуальные версии PHP (8.1+), расширения (mbstring, openssl, pdo_mysql/pgsql, intl и т.д.), Node/Vite для фронта при необходимости.
- Конфигурация — через `.env` + `config/**`; не храните секреты в коде/репозитории. Для прод используйте переменные окружения/secret storage.
- Настраивайте `APP_ENV`, `APP_DEBUG`, `APP_URL`, `APP_KEY` для всех стендов; включайте `APP_DEBUG=false` в prod.
- Разделяйте настройки очередей/кэша/сессий по стендам; используйте отдельные Redis namespaces/префиксы.

## Логи и наблюдаемость
- Включайте централизованное логирование, маскируйте PII и секреты. Настройте уровни логов по средам.
- Добавляйте метрики/алерты для ключевых операций, очередей, БД. Настройте мониторинг диска/CPU/памяти.

## Миграции и данные
- Миграции должны быть идемпотентными и сопровождаться сидерами/фабриками, если это нужно для тестов/демо.
- Не изменяйте данные вручную на проде; используйте миграции/сидеры/команды.
- При критичных изменениях схемы планируйте откаты и downtime-стратегии (транзакционные миграции, двойные записи/чтения, фиче-флаги).

## Деплой
- Деплой автоматизирован: `composer install --no-dev --optimize-autoloader`, `php artisan config:cache`, `route:cache`, `view:cache` (если совместимо), `php artisan migrate --force`, `php artisan queue:restart`.
- Собирайте фронтенд (vite/webpack) в production-режиме; выкладывайте собранные файлы (`public/build`).
- Очищайте/прогревайте кэш конфигов/роутов/вьюх после деплоя, если это безопасно.
- Не выкладывайте `.env`, `storage/logs`, `storage/framework/cache`, `vendor/`, `node_modules` в релизные архивы (кроме случаев, когда это осознанно).

## Релизы и пакеты деплоя
- Релизный слепок должен содержать исходники, `composer.lock`, lock-файлы фронтенда и собранные ассеты (если нужно), README с командами для проверки и деплоя.
- Деплой-пакет исключает `vendor/`/`node_modules` и секреты, включает инструкции и (опционально) архив.
- Фиксируйте версии/теги и сопроводительные заметки (changelog), включайте ссылки на батчи/таски.

## Интеграции
- Для внешних API: оборачивайте в клиенты с таймаутами, retry/backoff, логированием и трейсингом; храните ключи в `.env`.
- Webhook’и/входящие запросы: проверяйте подписи/токены, валидируйте payload, ограничивайте частоту.
- Email/SMS/push: используйте очереди, логируйте ошибки доставки, маскируйте PII.
