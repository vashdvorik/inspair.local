# Кэш и версии файлов

Цель: чтобы после любого обновления сайта посетители сразу получали новые стили, скрипты и картинки и не видели «глюков» от старого кэша. Файл `public/.htaccess` для этого не нужен.

## Что работает само
- **Адреса файлов с версией.** Все стили, скрипты, картинки, логотипы, манифест, превью для соцсетей и PDF подключаются как `файл?v=<время изменения>-<CACHE_EPOCH>` (`PublicUi::versioned`). Файл изменился, адрес другой, браузер скачивает новый.
- **Файлы внутри стилей** (шрифты Montserrat, цветные пятна `img/spots/*`) тоже с `?v=`. При замене такого файла увеличьте число после `?v=` в `public/design/inspire.css`, `pages.css` и `fonts.css`.
- **Игра в кабинете** собирается Vite с хешем в имени файла (`public/build`), версия не нужна.
- **Страницы (HTML)** отдаются с `Cache-Control: no-cache, must-revalidate`: браузер, прокси и CDN каждый раз проверяют, нет ли новой версии (`App\Http\Middleware\FreshPages`).
- **Разовая очистка кэша** у тех, кто заходил раньше: по HTTPS ответ несёт `Clear-Site-Data: "cache"`, а в куку `inspire_cache` записывается номер сброса, чтобы очистка не повторялась. Вход в кабинет и выбранный язык не затрагиваются.

## Как сбросить кэш у всех
В `.env` на сервере увеличьте номер и очистите конфиг:

```bash
CACHE_EPOCH=3
/usr/local/bin/ea-php83 artisan config:clear
```

После этого все адреса файлов станут новыми, а у каждого посетителя при следующем заходе один раз очистится кэш сайта.

## Ограничения
- `Clear-Site-Data` понимают Chrome, Edge, Safari, Opera; Firefox и встроенные браузеры мессенджеров могут его игнорировать. Для них работает версия адресов (`?v=`).
- Если у посетителя выключены куки, очистка будет срабатывать на каждой странице. Такие посетители встречаются редко.
